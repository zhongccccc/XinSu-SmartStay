# XinSu SmartStay · 芯宿智控

> 基于 RISC-V 的酒店自助入住与客房智能终端

一台 **进迭时空 SpacemiT K1** 自助入住一体机，配两块 **RK2206 + OpenHarmony** 终端板（门锁板 / 客房环境板），
完成「身份核验 → 人脸比对 → 选房 → 支付 → 绑定房卡 → 下发门锁凭证 → 开门 → 退房作废」的完整闭环。
全部业务与人脸比对在本地完成，不依赖云端。

## 技术亮点

- **端侧闭环，数据不出设备**：证件信息、人脸比对、门锁凭证都在本机处理；人脸图像不外传，断网可用。
- **开门鉴权下沉到门锁板**：开门码、房卡、指纹由门锁板本地校验，一体机只下发凭证——网络断开时房间照样能开。
- **自研人脸比对链路**：YuNet 检测 + 5 点对齐 + ArcFace 128 维特征 + 多帧双阈值判定。
  K1 实测：本人证件与本人现场 **0.67~0.71（判定通过）**，他人证件 **0.40（灰区转人工，不误放行）**。
- **语音引导全覆盖**：16 句播报覆盖入住到退房（含输错码、查无记录等异常分支），
  预生成音频 + 文本索引缓存，命中毫秒级出声，未命中回落板载离线合成。
- **设备即插即用**：三路 USB 转串口插拔后端口号会漂移，后端开机按协议握手自动认领，运行期不再扫描串口。

## 目录结构

```
app/
  backend/          业务状态机、设备抽象、HTTP + SSE 服务、SQLite
    devices/        门锁板 / 家居板 / 读卡器 / 身份证 / 扫码 / 相机 / 人脸
  web/              单页前端（无框架，SSE 驱动）
board_app/          门锁板固件（C，OpenHarmony 轻量系统）
home_app/           家居板固件（C，OpenHarmony 轻量系统）
face/               人脸比对模块（检测 / 对齐 / 特征 / 判定 / 质量门控）
tools/              运维脚本：串口收发、端口探测、双屏启动、语音生成
```

后端业务逻辑（HTTP / SSE / SQLite / 状态机）使用 Python 标准库，部署不需要虚拟环境；
摄像头取流与人脸比对调用系统镜像自带的 OpenCV、NumPy 与 ONNX Runtime。

## 实测数据（K1 样机）

| 项目 | 结果 |
|---|---|
| 本人身份证 vs 本人现场 | 0.6705 / 0.686 / 0.7087 / 0.683，4 次全部判定通过 |
| 他人证件 vs 本人现场 | 0.4041，落在灰区转人工，不误放行 |
| 画面中无人 | 返回重拍提示，不产生错误授权 |
| 人脸比对耗时 | 单帧检测 0.5~1.2s、单帧特征 0.15~0.5s；一次核验（3 帧）4.4~7.5s |
| 门锁板开锁行程 | 开锁 400ms / 上锁 600ms / 6 秒自动上锁 |

> 人脸阈值 0.45 / 0.32 目前基于小样本验证，正式部署需按现场样本重新标定。

## 快速开始

### 一体机

```bash
sudo cp -r app /opt/zhikong/
sudo cp systemd/zhikong-backend.service /etc/systemd/system/
sudo systemctl enable --now zhikong-backend
bash /opt/zhikong/tools/start_both.sh      # 启动界面（物理屏 + VNC）
```

### 终端板

两板都是 RK2206 + OpenHarmony，用 RKDevTool 烧录，**必须先「擦除 Flash」**：

| 行 | 文件 | 地址 |
|---|---|---|
| loader | `rk2206_db_loader.bin` | `0x00000000` |
| firmware | 门锁板 / 家居板镜像 | `0x00008000` |

烧完断电重启；擦除会清空门锁板凭证，需要重新入住或调用 `POST /api/lock/resync` 补发。

## 关键设计

- **串口端口自动认领**：后端开机对每个串口发一次协议探测，应答 `zk` 的是门锁板、`zh` 的是家居板、
  其余为读卡器；认领后各驱动只操作自己的端口。
- **板子离线就报错**：门锁板不可用时下发凭证直接返回失败，界面明确提示，不做静默降级。
- **板子主动上报**：家居板每 20 次采样打印一行心跳（实测约 10 秒一次），后端只解析不轮询，
  避免命令把板子的 shell 任务压垮。
- **人脸比对三级结论**：高分通过、低分重拍、中间灰区转人工，既不放宽阈值也不把客人卡在机器前。
- **人脸模块的两个工程取舍**：OpenCV 4.6 无法加载 2023 版 YuNet，改为 onnxruntime 直接推理并按官方公式解码；
  在这块板子上 FP32 模型比 INT8 快一倍，最终配置 FP32 + 4 线程。
