# 二代身份证读卡器 · 在 K1(riscv64) 上跑通厂商 aarch64 服务

> 结论：**读卡器已经在 K1 上真实读卡成功**（张三 / 4403**********1234 / 含照片）。
> 关键不是等厂商出 riscv64 包，而是让厂商的 aarch64 版服务在 riscv64 上跑起来。

---

## 一、为什么官方 DEB 装不上

SDK 里只有这些架构：

```
idreader_2.0_amd64.deb   idreader_2.0_arm64.deb
idreader_2.0_armhf.deb   idreader_2.0_loongarch64.deb
```

K1 是 **riscv64**，`dpkg -i` 会直接拒绝（架构不匹配），包里也没有 riscv64 的 `libsdtapi.so`。

---

## 二、走通的做法：binfmt_misc + 不重定根

### 2.1 原理

Ubuntu 装了 `qemu-user-static` 之后，内核通过 **binfmt_misc** 自动把 aarch64 的 ELF 交给
`qemu-aarch64-static` 执行，不需要手工 `qemu-aarch64 ...`。这样跑出来的进程**看到的是真实的
`/sys`、`/dev`**，libusb/udev 才能枚举到插在板子上的读卡器。

### 2.2 关键坑（之前卡了很久）

一开始我用的是：

```bash
qemu-aarch64-static -L /opt/zhikong/idreader/rootfs ./id_reader ...
```

`-L` 是"ELF 解释器前缀"，但它会把 **guest 的绝对路径整体重定根**。strace 显示服务去打开的是：

```
/opt/zhikong/idreader/rootfs/sys/class
/opt/zhikong/idreader/rootfs/dev/bus/usb
```

——设备路径被改写成 rootfs 里的空目录，永远找不到读卡器，于是报 `设备不存在`。

**改用 binfmt 直接执行（不带 `-L`）后就认到了**，报错从 `设备不存在` 变成 `找卡失败`，
放上身份证立刻读出了完整信息。

### 2.3 环境准备（已做好，重装时照此）

```bash
sudo apt-get install -y qemu-user-static          # 提供 binfmt 处理程序

# 1) 厂商 aarch64 二进制与库
/opt/zhikong/idreader/
├── bin/id_reader                 # SDK/Bin/Linux/aarch64/id_reader
├── lib/{libsdtapi,libbland,libidreader}.so
├── cfg/{idreader,http_service}.cfg
└── rootfs/                       # arm64 运行库（libc/libstdc++/libudev/libusb…）

# 2) 把 arm64 库放到 rootfs 的默认搜索路径
cp /opt/zhikong/idreader/lib/*.so \
   /opt/zhikong/idreader/rootfs/usr/lib/aarch64-linux-gnu/

# 3) 宿主 /lib 下补一个解释器软链（binfmt 执行时要用）
sudo ln -sfn /opt/zhikong/idreader/rootfs/usr/lib/aarch64-linux-gnu/ld-linux-aarch64.so.1 \
            /lib/ld-linux-aarch64.so.1
```

### 2.4 开机自启

`/etc/systemd/system/idreader.service`：

```ini
[Unit]
Description=ID card reader service (vendor aarch64 build via binfmt)
After=network.target

[Service]
Type=forking
PIDFile=/run/id_reader.pid
Environment=LD_LIBRARY_PATH=/opt/zhikong/idreader/rootfs/usr/lib/aarch64-linux-gnu:/opt/zhikong/idreader/lib
ExecStart=/opt/zhikong/idreader/bin/id_reader -a -p /opt/zhikong/idreader/cfg/
Restart=always
RestartSec=5
User=root

[Install]
WantedBy=multi-user.target
```

> `Type=forking` 是必须的：`-a` 参数会让它自己 daemon 化，父进程立刻退出 0；
> 用 `Type=simple` 会被 systemd 判成"启动完就退出"，陷入重启循环。

## 三、K1 侧配置

`/opt/zhikong/etc/config.json`：

```json
{
  "idcard": {
    "mode": "webapi",
    "url": "http://127.0.0.1:7846",
    "interval": 0.4,
    "timeout": 20
  }
}
```

- `timeout` 必须调到 **15–20 秒**：qemu 模拟下读一次卡要 **约 7.5 秒**，超时短了会被当成没读到
- `interval` 小一点没坏处，因为一次成功的读卡本身就要占满 7 秒

后端 `IdCardWebApi` 轮询该接口，拿到 `resultFlag=0` 就把证件灌进入住状态机（`ident → face`）。

## 四、验证

```bash
# 服务与端口
systemctl is-active idreader                 # active
ss -ltnp | grep 7846                         # 127.0.0.1:7846

# 直接读卡（放证）
curl -s 'http://127.0.0.1:7846/api/readCard?utf8=1'
# {"errorMsg":"OK","resultContent":{"name":"张三","idNum":"4403**********1234",...},"resultFlag":"0"}

# 一体机视角
curl -s 127.0.0.1:8080/api/health | python3 -m json.tool | grep -A4 idcard
# online: true
```

放证后屏幕会自动从「请放身份证」跳到「人脸」页，并显示「**张三 您好**」。

## 五、实测数据

| 项 | 值 |
|---|---|
| 读一次卡耗时 | 约 7.5 秒（qemu 指令翻译开销，可接受） |
| 识别到入流程 | 放证后 4–6 秒自动跳转 |
| 返回字段 | 姓名/证号/性别/民族/出生/住址/签发机关/有效期/照片(base64 JPEG) |
| 开机自启 | ✅ 已验证重启后服务自动起来并可读卡 |
| 日志中的 `HIDIOCGRDESC: Inappropriate ioctl for device` | qemu 不支持该 ioctl，**不影响读卡**，可忽略 |

## 六、备选方案（不推荐，仅记录）

- **Windows 当读卡机**：把 `windows/` 目录里的桥脚本放到装好厂商服务的 Windows 上跑，
  推证给 K1。详见 [06-身份证-读卡机远程接入](06-身份证-读卡机远程接入.md)。现在已无必要。
- **找厂商要 riscv64 版**：最干净，但没有它也能跑（本方案就是证明）。

## 七、如果换了读卡器型号

厂商服务按 VID/PID 找设备。换型号后：

1. `lsusb` 确认 VID/PID
2. 若服务不认，查看 `journalctl -u idreader -n 50` 是否出现 `hid: vid=... pid=...`
3. 必要时回退到 Windows 桥接方案
