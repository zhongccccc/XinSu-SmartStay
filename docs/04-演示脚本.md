# 3 分钟现场演示脚本

> 演示前 30 秒检查：屏幕是否在待机页、底部 7 个设备灯是否正常、音响是否插在 3.5mm 口。
> 若设备灯有红点，说明该外设没插——不影响演示，直接用界面上的「演示：模拟…」按钮。

---

## 开场（20 秒）

「这是芯宿·智控，用一颗进迭时空 K1（RISC-V 八核，2 TOPS）做边缘网关，
把酒店的自助入住、门锁、语音服务三端打通。整个交互在 800×480 触摸屏上，
所有推理和数据都在本地，不出酒店局域网。」

指一下底部状态栏：「这一排是实时的外设状态——触摸屏、摄像头、身份证、房卡读写、扫码、音响、门锁，插上就亮。」

## 第一段：自助入住全流程（90 秒）

1. 点「触摸屏幕开始入住」→ **身份核验**页，音响播报「请将身份证放在读卡区」
2. 刷身份证（或点「演示：模拟刷卡」）→ 显示「核验通过：陈思远」
3. **人脸采集**页，摄像头预览 + 绿色取景框 → 点「开始人脸核验」
4. **选房**页，12 间房型实时价格 → 点 8801（¥468）
5. **支付**页，金额 468 + 扫码口 → 扫码枪扫付款码（或点模拟）
6. **发房卡**页，RFID 脉冲动画 → 房卡放上读卡区（或点模拟）
7. **下发门锁**页（进度条）→ **完成页**：房号 8801 / 临时开门码 819058 / 房卡 UID / 门锁已授权

落点话术：
> 「从刷证到拿到开门凭证，全程 30 秒，替代前台 70% 的高峰人工。
> 门锁凭证是 K1 现场生成的，不走云端，断网也能开。」

## 第二段：语音服务（40 秒）

点右上角「语音服务」——

- 点「送一双拖鞋」→ 气泡回复「已为您呼叫服务：配送拖鞋，工单号 1，预计 8 分钟送达」+ 语音播报
- 点「开灯」→「好的，已为您打开灯光」
- 点「几点退房」→ 本地知识库应答

落点话术：
> 「服务工单在这里生成，前台 App 通过 `/api/workorders` 实时拿到房号、物品、状态，
> 从"打电话没人接"变成"可追踪的分钟级派单"。意图理解全部端侧，没有一次请求出网。」

## 第三段：技术底座（30 秒）

```bash
# 现场可切出终端演示（或用手机看）
curl -s http://192.168.60.40:8080/api/health | python3 -m json.tool
cat /proc/device-tree/model            # spacemit k1-x MUSE-Pi-Pro board
```

> 「主控是 8 核 RISC-V X60，16GB 内存，整机功耗 3.5W；
> 网关、入住状态机、设备驱动、TTS 全跑在这一颗芯片上，没有一台 x86 服务器。」

## 收尾（20 秒）

> 「目前身份证读卡器、扫码枪、RFID、摄像头还没插——它们都是标准 USB 设备，
> 插上后状态栏自动变绿，业务流程一行代码不用改。
> 门锁集成板今天下午到，协议已经定好并实现，接上就能演示真实开锁。」

## 冷场兜底

| 情况 | 处理 |
|---|---|
| 屏幕卡住 | `sudo systemctl restart zhikong-backend`，10 秒内恢复（kiosk 自动重连） |
| 摄像头没画面 | 正常，无摄像头；用「模拟」按钮继续 |
| 音响没声音 | 检查 3.5mm 是否插在板子耳机口；`aplay -D plughw:1,0 /opt/zhikong/app/assets/voice/*.wav` 测 |
| 想快速复位 | `curl -X POST http://127.0.0.1:8080/api/cancel` |
| 评委要扫码试试 | 拿任何带条码的东西在扫码枪前扫一下，界面上会实时显示读到内容 |

## 一句话卖点（背下来）

1. **全国产算力底座**：K1 + Bianbu，从芯片到系统到应用无 ARM/x86 依赖
2. **端侧闭环**：人脸、语音、凭证全在本地，数据不出酒店局域网，断网可用
3. **三端一体**：入住—开门—服务在同一个网关编排，不是孤立智能单品
4. **可复制**：同一套架构可平移到长租公寓、医院病房、园区宿舍
