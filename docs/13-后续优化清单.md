# 后续可优化项（按演示价值排序）

> 2026-11-05 · 当前状态：一体机 UI 已完成刷卡/输码退房；家居板 v17 在线；门锁板 USB 未通

---

## 🥇 第一优先：把第三块板接进系统

**现状**：智能家居板（v17）已经在线、传感器都在正常工作，但**数据和一体机毫无关系**——评委看到的只是"旁边有个小屏幕在显示温度"。

**可做**：
| 功能 | 说明 |
|---|---|
| 客房环境上屏 | 一体机加一块「客房环境」卡片，显示该房间温度/湿度/光照 |
| 燃气报警联动 | 燃气超阈值 → 自动生成工单 + 一体机弹红色告警 |
| 人体感应联动 | 检测到人 → 记录"客房有人"，退房时可提示"房间还有人" |
| 一键控制 | 一体机服务面板加「开灯 / 开风扇」，直接发 `zh light on` / `zh fan 60` |

**不需要刷固件**（家居板命令已经齐全），只改后端 + 前端。约 1 天。

---

## 🥈 第二优先：离线状态可见

**现状**：门锁板现在就是离线的，但界面上**完全看不出来**。客人办入住会卡在"下发凭证"转圈，工作人员也不知道为什么。

**可做**：
1. 顶部登录后显示设备状态灯（门锁板 / 家居板 / 摄像头）
2. 门锁板离线时，完成页显示黄色警示「门锁离线，请联系前台」
3. 办入住时如果门锁离线，**提前拦截**并提示，而不是走到最后才失败
4. 后端 SSE 断线时界面显示"连接中…"

约 2 小时。

---

## 🥉 第三优先：失败态的引导

**现状**：人脸比对失败、身份证读不出来，只有一行小字，没有明确动作。

**可做**：
- 统一的失败组件：大图标 + 原因 + [重试] + [呼叫前台] + [返回]
- 人脸连续失败 2 次 → 提示"请正对摄像头，摘下口罩"
- 身份证读不出来 → 提示"请将身份证放在读卡区中央，停留 2 秒"

约 3 小时。

---

## 4. 界面降噪

| 项 | 现状 | 建议 |
|---|---|---|
| 底部状态栏 | 7 个绿点全称，客人看不懂 | 缩成小圆点，或只在维护模式展开 |
| 右侧营销数字 | 30s / 70% / K1 | 保留但缩淡（给评委看，不给客人看） |
| 语音服务入口 | 右上角小按钮 | 客人可能根本不会点，考虑放大或加引导 |

约 1 小时。

## 5. 房间信息增强

**现状**：选房卡片只有房号、类型、标签、价格。
**可做**：加面积/朝向/床型图标；已订房卡片加"预计 X 点退房"（有订单数据可推）。

约 2 小时。

## 6. 门锁端体验（需要门锁板先连上）

| 指纹录入界面化 | 从命令行搬进一体机，客人可自助录 |

## ✅ 第一项已完成（2026-11-05）

**家居板已接入系统**：

| 内容 | 实现 |
|---|---|
| 驱动 | `backend/devices/home_board.py`，**被动监听**固件心跳（每 10 秒 `[zh] alive ...`），不再轮询轰炸 |
| 自动发现 | 遍历 `/dev/ttyUSB*`，认 `ZH|ACK|PING` |
| 接口 | `GET /api/home`、`POST /api/home/light|fan|beep` |
| 界面 | **仅前台模式可见**（长按 logo 3 秒进入）：语音服务面板内「客房环境」6 项指标 + 4 个控制按钮；顶栏温湿度胶囊与「前台模式」标记 |
| 告警联动 | 燃气 >2500 → 自动建工单 + 语音播报 + 界面弹窗（2 分钟去重） |
| 事件 | 人体感应 → SSE `home_pir`；燃气 → `home_gas` / `home_alarm` |
| 兜底 | 板子不在时可切模拟模式（`home_mode.sh sim`），界面标注 `simulated` |

离线验证：解析逻辑对心跳/事件/噪声/负温全部正确（`tools/test_home_parse_k1.py`）。

切换命令：
```bash
bash /opt/zhikong/tools/home_mode.sh real   # 真实板卡
bash /opt/zhikong/tools/home_mode.sh sim    # 模拟数据
```
