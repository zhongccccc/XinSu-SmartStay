# 芯宿·智控 · 系统架构与接口说明

## 1. 总体结构

```
┌──────────────────────────────────────────────────────────────┐
│  K1 板卡（MUSE Pi Pro / Bianbu 2.3.5）                        │
│                                                              │
│  ┌───────────────┐   HTTP/SSE   ┌──────────────────────────┐ │
│  │ Chromium      │◄────────────►│ backend (python3 标准库) │ │
│  │ kiosk 800×480 │              │  http.server + Threading │ │
│  └───────────────┘              │  ┌────────────────────┐  │ │
│         ▲ 触摸 fts_ts           │  │ Controller 状态机  │  │ │
│         │                       │  └─────────┬──────────┘  │ │
│                                 │  ┌─────────┴──────────┐  │ │
│  音响/麦克风 ES8326 ◄───────────┤  │ devices 设备层     │  │ │
│  摄像头 V4L2      ◄────────────┤  │ scanner / camera   │  │ │
│  身份证 桥接       ────────────►│  │ audio / idcard     │  │ │
│  RFID/二维码 HID  ────────────►│  │ lock 适配器        │  │ │
│  门锁板 串口/HTTP ◄───────────►│  └─────────┬──────────┘  │ │
│                                 │  ┌─────────┴──────────┐  │ │
│                                 │  │ SQLite 订单/工单/审计│ │ │
│                                 │  └────────────────────┘  │ │
│                                 └──────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

**设计约束**：riscv64 上没有 pydantic-core / opencv 之外的成熟 wheel，因此后端 **不依赖 Flask/FastAPI/pyserial**，全部用 Python 标准库实现（HTTP、SQLite、termios 串口、urllib）。唯一第三方依赖是摄像头用的 `python3-opencv`（系统预装）。

## 3. 入住状态机

```
idle ──start──► ident ──身份证──► face ──人脸──► room ──选房──► pay
  ▲                                                                 │
  │                                                                 │付款码
  └──────────────── done ◄── issue ◄── card ◄───────────────────────┘
                    (60s 无操作自动回 idle)
```

- 状态字段：`step / guest / idno / face / room / price / card_uid / lock_code / order_id / msg`
- 任何一步都可以 `POST /api/cancel` 中止
- 每个 transfer 都会 `BUS.publish("state", ...)`，前端通过 SSE 秒级刷新
- 每步同时触发 TTS 播报（语音包缺失时自动用 espeak-ng 现场合成并缓存）

## 4. 设备层设计

### 4.1 HID 扫码器（二维码识别器 / RFID 读卡器）

```
/dev/input/eventN ──裸读 input_event(24B)──► 按键字符流 ──回车/350ms静默──► 一次扫码
                        │
                        └ EVIOCGRAB 独占，防漏字到浏览器
```

- 分类依据：设备名关键字（`barcode|scanner|rfid|reader|读卡|二维码`）或 `config.json` 中的 `scanner_name_re`
- 路由：`step == pay` → 付款码；`step == card` 或设备类型为 rfid → 房卡 UID
- 现场识别新设备：`sudo python3 app/tools/selftest.py --hid 20`，插上设备扫一次，终端会打印设备名与内容

### 4.2 摄像头

- 遍历 `/dev/video*`，跳过 `vivi`（虚拟测试设备）、`mvx`（硬解码）、`aout/ain`（ISP 输出）
- 逐节点 `cv2.VideoCapture(path, CAP_V4L2)` 试开 + 试取帧，成功即锁定
- 输出：`/api/camera/snapshot.jpg`（抓拍）、`/api/camera/stream`（MJPEG 预览）

### 4.3 音频

- 播放：`aplay -D plughw:1,0`（ES8326），**必须 48kHz 单声道**，22.05kHz 会被拒
- 合成：`espeak-ng -v cmn -s 150` → ffmpeg 重采样 48k → 缓存到 `assets/voice/<md5>.wav`
- 队列串行播放，新流程开始时 `flush()` 打断上一条

### 4.4 门锁适配器

见 `03-门锁集成对接.md`。

### 4.5 串口 RFID 读卡器（V23B / CH340）

- 独立线程 `devices/rfid_serial.py`，9600 8N1，每 ~0.6s 发 `01 08 A1 20 00 01 00 76`
- 应答按「长度字节 + `~XOR` 校验」扫帧（帧前可能有 0x00 填充），解析出 2 字节卡类型 + 4 字节卡号
- 3 秒去重，避免同一张卡连续触发
- 触发后：`audit(scan)` + SSE `scan` 事件（界面 toast）+ 若 `step == card` 则 `on_card(uid)` 推进入住流程

### 4.6 身份证（WebAPI 客户端）

- `devices/idcard_web.py`：轮询厂商「身份证阅读服务」的 `GET /api/readCard?utf8=1`
- 服务可以在另一台机器上（今天用 Windows 笔记本），K1 只当客户端
- 识别到新证件号才触发，同一张卡不重复；服务离线不刷日志
- `mode: auto` 时启动即尝试，失败自动退回模拟刷卡，不影响演示

详见 [05-身份证读卡器接入](05-身份证读卡器接入.md)。

## 5. HTTP API

所有响应为 JSON（UTF-8），`Content-Type: application/json`。

### 5.1 状态

```http
GET /api/state
```
```json
{
  "step": "pay", "step_label": "支付", "msg": "请扫描付款码支付 ¥468",
  "guest": "陈思远", "idno": "440305199203182418", "face": "/photos/face_20261028_111020.jpg",
  "room": {"no": "8801", "type": "高级大床房", "price": 468, "floor": 8, "tags": ["园景","1.8m"]},
  "price": 468, "card_uid": null, "lock_code": null, "order_id": null,
  "rooms": [...], "inhouse": [...], "workorders": [...],
  "hotel": {"name": "芯宿·智控", "sub": "深圳湾科技园店"}
}
```

### 5.2 事件流

```http
GET /api/events        (Accept: text/event-stream)
```
事件主题：`state`（状态变化）、`scan`（扫码/刷卡）、`voice`（语音应答）、`hello`（握手）。

### 5.3 流程动作

| 接口 | Body | 说明 |
|---|---|---|
| `POST /api/session/start` | – | 开始入住（idle→ident） |
| `POST /api/idcard/inject` | `{"name":"张三","idno":"44030..."}` | 身份证桥接 |
| `POST /api/face` | `{"capture":true}` | 抓拍并标记人脸通过 |
| `POST /api/room/8801` | – | 选房 |
| `POST /api/pay` | `{"code":"2845..."}` | 付款码 |
| `POST /api/card` | `{"uid":"A1B2C3D4"}` | 房卡 UID |
| `POST /api/issue` | – | 生成开门码并下发门锁 |
| `POST /api/cancel` | – | 取消/复位 |

### 5.4 语音

```http
POST /api/voice  {"text": "帮我送一双拖鞋", "room": "8801"}
→ {"id": "1793236644143-517",
   "reply": "已为您呼叫服务：配送拖鞋，工单号 1，预计 8 分钟送达",
   "kind": "服务"}
```

> **`id` 用于去重**：同一条语音回复会走两条路——HTTP 响应 + SSE `voice` 事件。
> 前端按 `id|me` / `id|bot` 标记已渲染的消息，先到先渲染、后到的丢弃，
> 否则一次点按会在对话里出现两遍。新增推送路径时务必带上同一个 `id`。

意图类别：`灯光 / 空调 / 窗帘 / 服务 / 查询`，词表在 `config.py: VOICE_COMMANDS` 可扩展。

### 5.5 运维

| 接口 | 说明 |
|---|---|
| `GET /api/health` | 摄像头/门锁/声卡/TTS 状态 |
| `GET /api/devices` | 设备状态灯 |
| `GET /api/workorders` | 工单队列（前台 App 用） |
| `GET /api/audit` | 最近审计事件 |
| `POST /api/lock/open` | `{"room":"8801","method":"card"}` |
| `POST /api/sim/scan` | `{"code":"...","kind":"qr"}` 调试用 |

## 6. 部署与运维

```bash
# 后端（systemd，开机自启，崩溃重启）
sudo systemctl status zhikong-backend
sudo journalctl -u zhikong-backend -f

# kiosk（随图形会话自启）
bash /opt/zhikong/app/scripts/kiosk_session.sh

# 关闭/恢复开机进 kiosk
bash /opt/zhikong/app/scripts/disable_kiosk_autostart.sh
bash /opt/zhikong/app/scripts/enable_kiosk_autostart.sh

# 外设自检
python3 /opt/zhikong/app/tools/selftest.py --cam
python3 /opt/zhikong/app/tools/selftest.py --hid 20
```

**kiosk 启动链**：`sddm 自动登录 shiqi → labwc 会话 → ~/.config/labwc/autostart 钩子 → kiosk_session.sh → chromium --kiosk --disable-gpu`

> K1 的 GPU（PowerVR BXE-2-32）在 Chromium 122 下 EGL/Vulkan 初始化会段错误，必须 `--disable-gpu` 走软件渲染；800×480 下软件渲染帧率足够。

## 7. 数据库

```sql
orders(id, guest, idno, room, price, card_uid, lock_code, checkin_at, checkout_at, status, payload)
workorders(id, room, text, kind, status, created_at)
audit(id, ts, kind, payload)        -- idcard / face / pay / lock_issue / lock_open / scan / voice
```

审计是门锁"本地记录、断网可用"要求的落点：所有开门与发卡动作都留痕，可导出给 PMS。
