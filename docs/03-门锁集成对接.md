# 智能门锁板卡 · 对接说明（下午到货后照此联调）

> 目标：门锁集成板上电后 **1 小时内** 跑通「一体机下发凭证 → 门锁开锁 → 记录回传」。
> 适配层已完成，`app/backend/devices/lock.py` 支持三种传输，**不需要改业务代码**。

---

## 一、先决定一件事：走串口还是走网络

| 传输 | 适用 | 配置 |
|---|---|---|
| `serial` | 门锁板通过 USB-TTL / UART 直连 K1（最常见，推荐） | `/dev/ttyUSB0` 或 `/dev/ttyACM0`，115200 8N1 |
| `http` | 门锁板自带网口/WiFi，跑着 HTTP 服务 | `http://10.243.222.xx:9001` |
| `mock` | 今天的状态（无板卡） | 默认 |

改 `/opt/zhikong/etc/config.json`：

```json
{
  "devices": {
    "lock": {
      "transport": "serial",
      "serial": "/dev/ttyUSB0",
      "baud": 115200,
      "http": "http://127.0.0.1:9001",
      "token": "k1-lock"
    }
  }
}
```

改完重启：`sudo systemctl restart zhikong-backend`，然后
`curl -s http://127.0.0.1:8080/api/health | grep -o '"lock":[^}]*}'` 看 `online`。

> 注：`config.json` 是**深合并**——只写要改的字段即可，其余沿用默认值。

## 二、串口协议（ASCII 行协议，MCU 端最省事）

**物理层**：115200 8N1，无流控。每条消息一行，`\n` 结尾，UTF-8 JSON。

### 2.1 K1 → 门锁板

```json
{"cmd":"issue","room":"8801","code":"819058","card":"A1B2C3D4","ttl":1440,"guest":"陈思远"}
{"cmd":"open","room":"8801","method":"card"}
{"cmd":"ping"}
```

| 字段 | 含义 |
|---|---|
| `cmd` | `issue` 下发凭证 / `open` 开门 / `ping` 心跳 |
| `room` | 房号字符串 |
| `code` | 6 位临时开门码（有效期见 `ttl`，单位分钟） |
| `card` | 房卡 UID（十六进制串，可能为 `null`） |
| `ttl` | 凭证有效分钟数，一体机默认 1440（24h） |
| `guest` | 入住人姓名（仅日志用） |

### 2.2 门锁板 → K1（必须回一行）

```json
{"ok":true,"msg":"stored"}
{"ok":false,"msg":"storage full"}
```

- **2 秒内必须应答**，否则 K1 判定超时（`锁控板无应答（超时）`），一体机会停在"下发门锁"步并提示失败
- 失败时 `msg` 会原样显示在 kiosk 界面上，建议写人话（中文）

### 2.3 最小 MCU 实现（伪代码）

```c
void on_line(char *line) {
    if (strstr(line, "\"issue\"")) {
        save_cred(room, code, card, ttl);      // 写 Flash / 内存表
        printf("{\"ok\":true,\"msg\":\"stored\"}\n");
    } else if (strstr(line, "\"open\"")) {
        bool r = drive_lock();                 // 驱动电机/继电器，读门磁
        printf("{\"ok\":%s,\"msg\":\"%s\"}\n", r ? "true" : "false", r ? "opened" : "jam");
    } else if (strstr(line, "\"ping\"")) {
        printf("{\"ok\":true,\"msg\":\"pong\"}\n");
    }
}
```

## 三、HTTP 协议（若门锁板自己联网）

| 方法 | 路径 | Body | 应答 |
|---|---|---|---|
| POST | `/issue` | `{"room","code","card","ttl"}` | `{"ok":true,"msg":"stored"}` |
| POST | `/open` | `{"room","method"}` | `{"ok":true,"msg":"opened"}` |
| GET | `/ping` | – | 200 即可 |

请求头带 `X-Token: k1-lock`（可配）。

## 四、联调步骤（照做即可）

### Step 1 · 认口

门锁板插上后：

```bash
ls -l /dev/ttyUSB* /dev/ttyACM*            # 找到设备节点
dmesg | tail -20                            # 确认驱动/VID:PID
python3 /opt/zhikong/app/tools/selftest.py  # 自检报告里看 [串口] 段
```

### Step 2 · 先裸测串口，不碰业务

```bash
# 发一条 issue，看门锁板是否回 ack
printf '{"cmd":"issue","room":"8801","code":"123456","card":"A1B2C3D4","ttl":60}\n' > /dev/ttyUSB0
cat /dev/ttyUSB0        # 另开一个终端，应看到 {"ok":true,...}
```

若没有 `cat` 回显 → 先查波特率/接线/是否要拉 DTR。

### Step 3 · 切配置

```bash
sudo tee /opt/zhikong/etc/config.json > /dev/null <<'EOF'
{"devices":{"lock":{"transport":"serial","serial":"/dev/ttyUSB0","baud":115200}}}
EOF
sudo systemctl restart zhikong-backend
curl -s http://127.0.0.1:8080/api/health | python3 -m json.tool | grep -A3 lock
```

### Step 4 · 跑一遍完整入住

在触摸屏上点「触摸屏幕开始入住」→ 身份证（模拟）→ 人脸 → 选房 → 支付（模拟）→ 房卡（模拟）→ **下发门锁**。
此时门锁板应收到 `issue`，K1 收到 `{"ok":true}`，界面进入完成页并显示 6 位开门码。

也可以纯命令行验证：

```bash
B=http://127.0.0.1:8080
```


## 五、如果门锁板不是"行协议"，而是这两个常见形态

**A. 板子只做透传（串口收到的就是裸字节帧）**
在 `lock.py` 的 `SerialLock._rpc()` 里换掉 `json.dumps` 那一行，改成你们的帧格式（含 CRC/包头），其余逻辑不变。

**B. 板子走 MQTT**
K1 上目前没装 paho-mqtt。两条路：
- `pip3 install --break-system-packages paho-mqtt`（有网即可），在 `lock.py` 加一个 `MqttLock` 类；
- 或在门锁板侧起一个 HTTP 小服务，用现成的 `HttpLock`。

**C. 板子走 BLE / NFC 读头**
这类一般由门锁板内部完成，K1 侧仍走 `issue` 下发凭证，协议不变。

## 六、需要向门锁厂/工程师确认的 6 个问题

1. 通信物理层：UART（几号口、波特率）还是网口/WiFi？
2. 帧格式：ASCII 行 / 二进制帧？有无 CRC、包头包尾？
3. 凭证怎么存：一次性还是有效期？断电是否保持？最多存几条？
4. 开门反馈：靠门磁还是电机到位信号？有没有"开锁成功"回执？
5. 断网策略：本地凭证校验是否独立于 K1？断电恢复后行为？
6. 审计回传：开门记录是主动推送还是轮询？

把这 6 条问清，剩下的就是改 20 行协议代码。

## 七、当前 mock 行为（今天演示时的表现）

- `issue`：延迟 450ms 模拟串口往返，写 `audit(lock_issue)`，返回 `stored`
- `open`：立即返回，写 `audit(lock_open)`
- 界面上「智能门锁」状态灯：mock 时显示绿灯 + `mock` 字样
- 切到 `serial` 且板子没接时：状态灯变红，入住流程在"下发门锁"步报错并停留（可重试），**不会崩溃** —— 这是刻意设计的降级表现
