## 二、通信方式：shell 子命令（关键设计）

板子的日志串口同时被系统 shell 占用。如果我们的应用直接读这个 UART，
会和 shell 抢字节，命令经常被吃掉一半。

所以协议做成了 **shell 子命令**——`osCmdReg()` 注册 `zk`，由 shell 完成行解析后再交给应用，
彻底避免竞争：

```
K1 发送（\r 结束）       板子回打印（行首 ZK|）
zk ping                  ZK|ACK|PING|OK|rk2206-zk-v1
zk issue 8801 123456 CARD01 1440
                         ZK|ACK|ISSUE|OK|room=8801
zk open 8801             ZK|ACK|OPEN|OK
                         ZK|EVT|DOOR|open
zk revoke 8801           ZK|ACK|REVOKE|OK
```

控制台的 `OHOS # ` 提示符、命令回显、系统日志都会混在流里，
K1 侧只认含 `ZK|` 的行，其余全部丢弃。

## 三、引脚（来自引脚使用表）

| 部件 | 丝印 | 引脚 | GPIO 号 | 复用 |
|---|---|---|---|---|
| **电机（锁体）** | C6 | `GPIO0_PC6` | **22** | PWM6_M0 |
| **键盘** | C7 | `GPIO0_PC7` | **23** | KEY_ADC（电阻分压，单 ADC 读 16 键） |
| **NFC** | D5/D6 | `GPIO0_PD5/PD6` | 29/30 | I2C0 SDA/SCL |
| 人体感应 | A3 | `GPIO0_PA3` | 3 | 可当门磁/防拆 |
| 蜂鸣器 | C5 | `GPIO0_PC5` | 21 | PWM5_M0 |
| 报警灯 | A5 | `GPIO0_PA5` | 5 | GPIO |
| 三色灯 | B4/B5/D0 | `PB4/PB5/PD0` | 12/13/24 | PWM |
| **日志串口** | A6/A7 | `GPIO0_PA6/PA7` | — | **UART1**（K1 接的就是这个） |

GPIO 编号规则（`device/rockchip/rk2206/adapter/include/lz_hardware/gpio.h`）：
`PA0..PA7 = 0..7`，`PB0..PB7 = 8..15`，`PC0..PC7 = 16..23`，`PD0..PD7 = 24..31`

UART 对应（`hal_iot_uart.c`）：**IoTUart id 0 = PA6/PA7（日志口）**，id 1 = PB2/PB3。

## 四、K1 侧（已完成）

| 文件 | 作用 |
|---|---|
| `app/backend/devices/lock_board.py` | 串口驱动：发 `zk` 命令、收 `ZK|` 行、等 ACK（发送前清旧应答，防时序竞争） |
| `app/backend/devices/lock.py` | `BoardLockAdapter`：`transport: auto` 时板子离线自动退化 mock，每 10s 重试 |
| `app/backend/core/model.py` | 退房/取消时自动 `revoke` 作废板子上的凭证 |
| `app/backend/main.py` | 门锁事件 → 审计 + SSE；界面弹提示（门已打开/关闭、刷卡、指纹、告警） |
| `app/tools/lock_board_sim.py` | 板子模拟器（含 shell 回显与提示符），固件没刷也能联调 |

配置：

```json
{"devices": {"lock": {"transport": "auto", "port": "/dev/ttyUSB1", "baud": 115200}}}
```

**auto 语义**：启动时 ping 板子，应答就用板子；不应答用 mock 并后台每 10 秒重试，
固件刷好后无需重启，自动接管。

## 六、键盘 / NFC / 指纹

| 部件 | 做法 |
|---|---|
| 4×4 键盘 | PC7 是 `KEY_ADC`：`IoTAdcRead(7, &val)` 读电压，按实测分档映射 16 个键；`#` 确认时 `cred_check()` |

| 门磁/防拆 | PA3 电平变化已实现，上报 `ZK\|EVT\|DOOR\|open\|close` |

## 七、演示话术

1. 一体机完成入住 → **开门码 + 房卡写进门锁板**（板子真的收到 `zk issue`）
2. 客人在门锁键盘输码 → 板子**本地校验** → 电机动作 → 上报 `ZK|EVT|DOOR|open`
3. 一体机界面弹出「门已打开」并记入审计
4. 退房时 `zk revoke` 一键作废，板子本地凭证清空
5. **断网可用**：凭证存在板子本地，K1 掉线照常开门

## 八、编译踩坑记录（重装环境时照做）

编译已跑通（`isoftstone-rk2206 build success`，Firmware.img 2.0 MB，
`liteos.map` 里 44 处 `zk_lock` 引用）。中间修了 4 个问题：

### 8.1 hb 解析输出崩溃

```
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xef ...
```

hb 用 `encoding='utf-8'` 严格模式读 ninja 输出，遇到非 UTF-8 字节就崩。
修 `/usr/local/lib/python3.8/dist-packages/hb/common/utils.py` 的 `exec_command()`：

```python
process = subprocess.Popen(cmd, stdout=subprocess.PIPE, stderr=subprocess.STDOUT,
                           encoding='utf-8',
                           errors='replace',        # ← 加上这一行
                           **kwargs)
```

### 8.2 `shell.h` 的 POSIX 依赖

直接 `#include "shell.h"` 会报：

```
error: unknown type name 'pthread_mutex_t'
error: 'PATH_MAX' undeclared
```

精简内核的 shell.h 假设了完整 POSIX 环境。**不要包含它**，只声明用到的符号：

```c
#define ZK_CMD_TYPE_STD   1          /* CMD_TYPE_STD */
#define ZK_XARGS          0xFFFFFFFFu/* XARGS */
typedef unsigned int (*zk_cmd_cb_t)(unsigned int argc, const char **argv);
extern unsigned int osCmdReg(int cmdType, const char *cmdKey,
                             unsigned int paraNum, zk_cmd_cb_t cmdProc);
```

### 8.3 注释里的 `0-9/*/#` 会提前闭合注释

`/*` 后紧跟 `/` 构成 `*/`，注释提前结束，后面的 `#` 变成非法预处理指令。
写中文注释时避免 `/*`、`*/` 这种字符组合。

### 8.4 库编出来了但没链接（最隐蔽）

`hb build` 成功，但 `liteos.map` 里搜不到 `zk_lock` —— SDK 的
`device/rockchip/rk2206/sdk_liteos/Makefile` 用的是**固定库列表**：

```make
app_LIBS = -lshellcmd -lzk_lock     # ← 必须手动加
```

它位于 `-Wl,--whole-archive` 段内，加上后才会被强制链接。
**只改 `applications/.../BUILD.gn` 是不够的**，这一步最容易漏。

验证是否真的进去了：

```bash
grep -c zk_lock out/rk2206/isoftstone-rk2206/liteos.map     # 应 > 0
strings out/rk2206/isoftstone-rk2206/liteos.elf | grep 'rk2206-zk'   # 应能看到版本串
```
