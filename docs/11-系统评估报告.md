## 二、🔴 高危问题（上线前必须解决）

### 1. 所有 HTTP 接口零鉴权
**证据**：`grep Authorization main.py` → 0 处

局域网内**任何人**都能：
```bash
curl -X POST 192.168.1.120:8080/api/cancel          # 强制复位
curl -X POST .../api/checkout -d '{"room":"8808"}'  # 任意房间退房
curl -X POST .../api/lock/code -d '{"pin":"xxxxxx"}' # 尝试开门
```
**影响**：演示环境可接受；实际酒店场景属于严重漏洞。
**修复**：加一个 token 校验中间件（前端从 URL 参数取 token）。约 1 小时。

### 2. 后端以 root 运行
**证据**：`systemctl cat` → `User=root`
**影响**：后端一旦被攻破 = 整机沦陷；配合问题 1 风险叠加。
**修复**：建专用用户 + 串口 dialout 组。约 1 小时（需处理 /dev/ttyUSB 权限）。

### 3. 脚本里硬编码 sudo 密码
**证据**：`mode_kiosk.sh`、`install_desktop_app.sh`、`disable_kiosk_autostart.sh`、`enable_kiosk_autostart.sh`、`mode_desktop.sh` 都含 `123456`
**影响**：密码明文躺在磁盘上，且被多次通过网络传输。
**修复**：改用 sudoers 免密白名单，或 systemd-run。约 30 分钟。

### 4. 日志无轮转
**证据**：`backend.out` 已 **4.0 MB** 且持续增长
**影响**：长期运行会写满根分区，导致系统异常。
**修复**：logrotate 配置（按大小切分）。约 15 分钟。

### 5. 设备掉线无感知、无自动恢复
**证据**：`lock.py` 里 `_reprobe` 只在 `_use_mock` 为真时运行；板子在 **board 模式**下掉线后不会重连
**影响**：
- 拔掉门锁板，界面照常走流程，凭证下发失败**只在日志里**
- 必须重启后端才能恢复
**修复**：
1. 健康检查定时 ping，失败则置 offline
2. 界面顶部显示"门锁离线"红色横幅
3. 通用重连线程（不区分 mock/board）。约半天。

## 三、🟠 功能不完整（影响演示说服力）

### 6. 智能家居板数据未进系统
**现状**：温湿度/光照/燃气/人体只显示在板载 LCD，系统完全不知道
**影响**：这块板目前是"孤岛"，没体现"智能家居"与酒店系统的联动价值
**修复**：后端加 `home_board` 驱动，解析 `ZH|` 事件，入库并推送，燃气报警自动生成工单。约 1 天。

### 7. 门锁板键盘 `2` 键不可用
**现状**：按 2 会读成 0，生成开门码时避开了数字 2
**影响**：客人如果自己想一个含 2 的密码会失败；评委若随机按可能踩到
**修复**：需要示波器抓那一列的波形，或换 TTP229 扫描时序。**不确定工时**。

### 8. 凭证有效期未执行
**现状**：`ttl_min` 只存不用，凭证永不过期（除非退房）
**影响**：客人离店不办退房，开门码一直有效——安全漏洞
**修复**：板端加定时清理 + 下发时记录到期时间。约半天。

### 9. 指纹录入只能命令行
**现状**：需要人工执行 `zk en1` → 按手指 → `zk en2 0`
**影响**：演示时无法让客户现场录入指纹，只能预先录好
**修复**：板端加"录入模式"（OLED 提示按几次），一体机加引导页。约 1 天。

### 10. 燃气报警不联动系统
**现状**：板载只有显示标志，不通知任何人
**影响**：安全类功能没闭环
**修复**：同第 6 项，一起做。

### 11. 房卡只能绑一张、换卡要退房
**现状**：`cred_bind_card` 一条凭证只绑定一张卡，重复刷卡无效
**修复**：加 `zk unbind <room>`。约半天。

### 12. 门锁板 OLED 无字库
**现状**：只能画圆点表示"输了几位"，看不到房间号、提示语
**影响**：用户体验偏弱，无"欢迎 8808"这类信息
**修复**：需要嵌入字模（12×12 或 16×16）。约 1 天。

## 六、值得肯定的部分

1. **完整业务闭环**：不是拼凑的演示，而是从入住到退房走通了真实硬件
2. **安全模型正确**：开门鉴权在门锁端，断网也能用——这是真实门锁的架构
3. **串口自愈**：端口号漂移后能自动发现（虽然只在启动时）
4. **文档沉淀**：踩过的坑（TTP229 时序、电机行程、burn 需擦除）都有记录
5. **三块板协同**：K1 做业务、门锁板做安全执行、家居板做环境感知，职责清晰
