# 返回键 & 桌面程序

## 一、返回键（每个界面）

右上角新增「‹ 返回」，位置在时钟左边。

| 当前界面 | 返回后 | 同时清掉的数据 |
|---|---|---|
| 身份核验 `ident` | 待机 `idle` | 全部（客人/房间/卡号…） |
| 人脸 `face` | 身份核验 | 房间、价格、房卡 |
| 选房 `room` | 人脸 | 房间、价格 |
| 支付 `pay` | 选房 | 房卡 |
| 房卡 `card` | 支付 | 房卡 |
| 完成 `done` | 待机 | 全部 |

- 待机页不显示返回键（没有上级）
- 「下发门锁」是瞬态步骤（不到 1 秒自动过去），也不显示
- 每次返回都会写一条 `audit(back)`，记录 `from → to`

**后端**：新增 `POST /api/back`，由 `Controller.back()` 处理回退与数据清理。
**前端**：顶栏按钮，`render()` 里按步骤显隐。

> 注意：回退到「身份核验」时，如果身份证还压在读卡器上，约 5 秒后会再次读到并自动前进——
> 这是预期行为（卡还在），换人操作时把卡拿开即可。

## 二、桌面程序

一体机现在有两套启动方式，一条命令切换。

### 2.1 桌面模式（像普通程序一样用）

```bash
zhikong desktop      # 开机进桌面，不自动全屏
```

开机后自动登录到桌面，桌面上有一个 **芯宿·智控** 图标：

![桌面图标](shots/desktop_icons.png)

**单击图标**即启动一体机（全屏）。应用菜单里也能找到（`Utility` 分类）。

> 触摸屏上双击很容易点不中，所以已经把 pcmanfm-qt 改成 `SingleClick=true`（单击打开）。
> 见 2.5 的坑位说明。

### 2.2 怎么退出（重要）

应用是全屏的，没有标题栏。**长按左上角「芯宿」logo 1.5 秒**，会弹出确认框：

![退出确认](shots/exit_mask2.png)

点「退出到桌面」即关闭界面、回到桌面，**后端服务继续运行**（下次点图标秒开）。

其它退出方式：

| 方式 | 操作 |
|---|---|
| 长按 logo | 触摸屏唯一方式（推荐） |
| 键盘 | `Alt + F4`（接了键盘时） |
| 命令行 | `zhikong stop`（SSH 远程） |

### 2.3 kiosk 模式（开机自动全屏，展会/演示用）

```bash
zhikong kiosk        # 开机自动全屏进一体机
```

### 2.4 命令行工具

```bash
zhikong status       # 后端/读卡服务/界面/摄像头/身份证/RFID 一览
zhikong start        # 启动界面（等同单击图标）
zhikong stop         # 只关界面，后端继续跑
zhikong restart      # 重启后端
zhikong desktop      # 切桌面模式
zhikong kiosk        # 切 kiosk 模式
```

### 2.6 窗口 vs 全屏

启动器默认全屏（800×480 触摸屏没有窗口边框的余地）。接 HDMI 大屏调试时用窗口模式：

```bash
ZHIKONG_MODE=window /opt/zhikong/app/scripts/app_launch.sh
```

## 三、已知坑

### 3.1 从 SSH 起的界面收不到触摸

如果界面是**从 SSH 会话**里 `kiosk_session.sh` 拉起的，窗口可能拿不到 seat 焦点，
表现为**怎么点都没反应**（点击信标 `[ui]` 不打印任何事件）。

**解决**：让界面由图形会话自己拉起：

```bash
sudo systemctl restart sddm
```

从桌面单击图标启动的实例不受影响（父进程在会话内）。

### 3.2 改 pcmanfm 设置会被写回

pcmanfm-qt 在**退出时会把内存里的设置写回** `~/.config/pcmanfm-qt/lxqt/settings.conf`，
所以 `sed` 改完再 `kill`（SIGTERM）等于白改。

正确顺序：先 `sed` 改文件 → 再 `kill -9`（不给它保存机会）→ 让 `lwrespawn` 拉起新实例。
但 `kill -9` 之后桌面可能变成黑屏（壁纸和图标不画），**最稳的是直接重启会话**：

```bash
sudo systemctl restart sddm
```

设置文件在会话启动时被读取，重启后生效且不会被覆盖。

排查手法：看后端日志有没有 `[ui] down/click` 行——

```bash
grep '\[ui\]' /opt/zhikong/logs/backend.out | tail
```

有事件但 target 不对 = 坐标问题；**完全没有事件** = 输入没进窗口，重启会话即可。
