# 二代身份证 · 借读卡机远程接入（无 riscv64 服务时的正解）

## 一、现状与判断

| 事实 | 说明 |
|---|---|
| 读卡器硬件 | `0102:0001 ZDG ID Reader HID`，插在 K1 上能被识别（hidraw 节点在） |
| K1 上能不能读 | ❌ 厂商只有 `x86_64 / aarch64 / armhf / arm64 / loongarch64 / mips64el`，**没有 riscv64** |
| 读卡器协议 | 实测能收到我们发的指令并回 `no card!(11->0)`，说明**通道是通的**；但射频/SAM 握手是厂商私有的，裸发 APDU 不会开射频 |
| 厂商服务在哪 | **10.243.222.130（本机）** 已装「身份证阅读服务」，系统服务运行，监听 `127.0.0.1:7846` |
| 该服务接口 | `GET http://127.0.0.1:7846/api/readCard?utf8=1`，返回结构化证件 JSON（结构见第五节） |

**结论：读卡器必须插在那台装有厂商服务的 Windows 上，K1 只当业务机。** 两条路，任选其一。

```
                    ┌──────────────────────────────┐
   身份证 ──USB──►  │ Windows 10.243.222.130       │
                    │ 身份证阅读服务 (系统服务) :7846│
                    └──────────────┬───────────────┘
                                   │ HTTP（同网段）
                    ┌──────────────▼───────────────┐
                    │ K1 192.168.60.40             │
                    │ 一体机 kiosk / 入住状态机      │
                    └──────────────────────────────┘
```

## 二、方案 B：双击一个桥（推荐，不用管理员权限）

把本仓库 `windows/` 文件夹复制到一个方便的位置（或直接在 `E:\zhikong\windows\` 用），
确认**读卡器插在这台 Windows 上**、屏幕右下角「身份证阅读服务」在运行，然后双击：

```
windows\启动读卡桥.bat
```

窗口会打印：

```
[15:47:55] K1 已连通
[15:47:55] 读卡服务已响应，开始监听
[15:48:12] 推送成功 -> 张三 440306200510071234
```

它做的事：轮询 `127.0.0.1:7846` → 读到证 → POST 到 K1 的 `/api/idcard/inject`。
不需要改服务配置、不需要开防火墙入站（主动往外连）、断了会自动重连。
**演示期间这个窗口要一直开着。**

## 三、方案 A：让服务监听局域网（不用常开窗口）

K1 侧已经预配置成 `http://10.243.222.130:7846`，你只要在 Windows 上放开监听，K1 立刻能读。

1. 找到读卡服务的 `http_service.cfg`（服务是系统权限跑的，可在
   `C:\Program Files*`、`C:\ProgramData`、或托盘图标右键「打开文件所在位置」里找）
2. 把 `"listen_addr" : "127.0.0.1"` 改成 `"listen_addr" : "0.0.0.0"`
3. 重启「身份证阅读服务」（或在服务管理器里重启对应服务）
4. 管理员 PowerShell 放行端口：

   ```powershell
   New-NetFirewallRule -DisplayName "IDCardService 7846" -Direction Inbound -Protocol TCP -LocalPort 7846 -Action Allow
   ```

5. K1 上验证：

   ```bash
   curl -s http://10.243.222.130:7846/api/readCard?utf8=1
   ```

放证后 K1 会自动从「请放身份证」跳到「人脸采集」。

## 四、两台机器必须在同一网络

K1 目前在手机热点 `RedmiK70` 的 `10.243.222.0/24` 下。
扫描确认该网段有两台 Windows：`10.243.222.130`（当前这台）、`10.243.222.8`（读卡机）。

如果读卡机换了网络，**把它也连到同一个热点**，或把 K1 连到读卡机所在的网络，然后改 `idcard.url`。

## 五、K1 侧已经做好的部分（不用再改）

- `app/backend/devices/idcard_web.py`
  - 解析厂商真实返回结构：`resultFlag` / `resultContent.{idNum,name,gender,birthday,address,issueOrg,effectDate,expireDate,nation,photo}`
  - 性别编码 `1→男 2→女`，民族编码 `01→汉`（内置常用码表）
  - 同一张证不重复触发；服务离线静默重试
- `/api/idcard/inject`：给桥推卡用，字段 `{name, idno, sex, nation, birth, addr, police, valid_from, valid_to}`
- `/api/health` 里能看到 `idcard: {mode, url, online}`，一眼判断通没通
- 读卡成功会触发入住状态机：`ident → face`，同时写 `audit(idcard)` 留痕

## 七、如果以后拿到 riscv64 版服务

1. 放到 `/opt/zhikong/idreader/bin/`（已有 aarch64 版目录结构可参考）
2. 起服务，监听 `127.0.0.1:7846`
3. `config.json` 改 `"url": "http://127.0.0.1:7846"`
4. **K1 代码一行不改**，读卡器插回板子即可

这也是向厂商提 riscv64 需求的理由：现在整套业务已经就绪，只差一个架构的二进制。
