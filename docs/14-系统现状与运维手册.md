# 系统现状与运维手册

> 更新：2026-11-05 深夜
> 适用：芯宿·智控自助一体机（SpacemiT K1）+ 智能门锁板 + 智能家居板

## 一、当前固件与设备

| 设备 | 型号 / 固件 | 串口 | 说明 |
|---|---|---|---|
| **一体机** | SpacemiT K1 / Bianbu 2.3.5 | — | 大堂自助机，服务 `zhikong-backend` |
| **智能门锁板** | 通晓 Smart_Lock / `rk2206-lock-v59` | 自动认领 | 房间门锁模拟 |
| **智能家居板** | 通晓 TX-SMART-R / `rk2206-home-v26` | 自动认领 | 客房环境 |
| **读卡器** | CH340 @9600 | 自动找 | 刷房卡 / 退房 |
| **身份证读卡器** | miniSTREAK HID | — | 走 webapi(7846) |
| **扫码器** | Worlde USBScn | — | 付款码 |

> ⚠️ **三个 CH340 的端口号每次插拔都会变**（ttyUSB0/1/2/3/5 都可能），
> 所以后端**开机时自动认领**：谁回 `ZK` 就是门锁板，谁回 `ZH` 就是家居板，
> 剩下的给读卡器。**不要手改配置里的端口号。**

## 三、烧录流程（每次都一样）

### 通用步骤
1. 按住 **MASK** → 点 **RESET** → 松开，进入 MASKROM（工具提示 `Found One MASKROM Device`）
2. RKDevTool 切到**高级功能** → **擦除 Flash**（**必须做**，否则残留分区会 boot loop）
3. 切回**下载镜像**：
   | 行 | 文件 | 地址 |
   |---|---|---|
   | Loader | `rk2206_db_loader.bin` | `0x00000000` |
   | Firmware | 对应固件（见下表） | `0x00008000` |
4. 点 **Run**，等绿色成功
5. **断电重启**（拔 USB 等 3 秒）

### 固件对照
| 板子 | 文件 |
|---|---|
| 紫色门锁板 | `E:\zhikong\fs\LOCK_v59.img` |
| 智能家居板 | `E:\zhikong\fs\HOME_v26.img` |
| ⚠️ 不要烧错 | `Firmware.img` / `Firmware_home.img` 是旧的 |

> **擦除会清空板上的凭证/绑定**：门锁板烧完要**重新办一次入住**把开门码写进去，房卡也要重新刷一次绑定。

## 四、常见问题

### 板子不响应 / 后端显示 offline
**症状**：`/api/health` 里 `online=False`，或串口命令没回应

**处理**：
1. **断电重启那块板子**（拔 USB 等 3 秒）—— 90% 的问题这一步解决
2. 还是不响应 → 检查 USB 线（有些线只有电源没有数据）
3. 确认三个 CH340 都在：`lsusb | grep -c 7523` 应为 **3**

### 端口号又变了
不用管，重启后端即可自动认领：
```bash
sudo systemctl restart zhikong-backend
```

### 刷房卡没反应
1. 先看读卡器是否在工作：日志里应有 `[rfid] card uid=XXXX`
2. 没有 → 换 USB 口/线（这个读卡器硬件不太稳定）
3. 即使读卡器坏了，**入住不会卡住**（20 秒自动放行），客人可用开门码

### 门锁板不认密码
- 确认板子在线且已下发凭证（重新办一次入住）
- 密码错误时屏幕应出现 ✕；没出现说明固件不是 v59

### 屏幕颜色怪
这块 2.4" 屏是硬件反色的，所以界面用纯黑白。若以后换成不反色的屏，改配色即可。

## 五、常用运维命令

```bash
# 服务
sudo systemctl restart zhikong-backend
systemctl status zhikong-backend

# 设备状态
curl -s http://127.0.0.1:8080/api/health | python3 -m json.tool
curl -s http://127.0.0.1:8080/api/home | python3 -m json.tool

# 两个屏幕（物理屏 + VNC）
bash /opt/zhikong/tools/start_both.sh

# 家居板：真实 / 模拟数据
bash /opt/zhikong/tools/home_mode.sh real
bash /opt/zhikong/tools/home_mode.sh sim

# 给板子发命令（自动找端口，需先停后端独占串口）
sudo systemctl stop zhikong-backend
sudo python3 /opt/zhikong/tools/zk_send.py "zk ping"
sudo python3 /opt/zhikong/tools/zh_send.py "zh env"
sudo systemctl start zhikong-backend

# 排查：每个口在说什么
sudo systemctl stop zhikong-backend
sudo python3 /opt/zhikong/tools/raw_listen.py
sudo systemctl start zhikong-backend
```

## 六、板子命令集

### 门锁板（`zk`）
```
zk ping                       # 心跳，返回版本/开锁次数/OLED状态
zk issue <room> <code> <card|-> <ttl_min>   # 下发凭证
zk open <room>                # 远程开锁
zk code <pin>                 # 校验开门码
zk revoke [room]              # 作废凭证（按房间）
zk en1 / en2 <id>             # 录入指纹
zk oled on|off                # 开关 OLED
zk nfc                        # NFC 调试
```

### 家居板（`zh`）
```
zh ping                       # 心跳
zh env                        # 温湿度/光照
zh pir / zh gas               # 人体 / 燃气
zh light on|off|auto          # 灯
zh fan 0-99 | on | off        # 风扇
zh beep <ms>                  # 蜂鸣器
```
> 固件每 10 秒自动打印 `[zh] alive #N t=.. h=.. lux=.. gas=.. pir=..`，后端靠这行更新数据。

## 七、已知限制

| 项目 | 说明 |
|---|---|
| 门锁板键盘 `2` 键 | 读数不稳（与 0 撞位），开门码已避开数字 2 |
| 门锁板 OLED | 无字库，只能画图形（锁图标、圆点、✕/✓） |
| 家居板 LCD | 硬件反色 + 字库有限（已补 18 字，仍非全字库） |
| 读卡器 | 硬件不稳定，偶发无响应 |
| 接口鉴权 | 无 token，局域网内可直接调用（演示环境可接受） |
| 日志 | 未轮转（`backend.out` 会持续增长） |
| 人脸 | 测试模式自动放行，未做真实比对 |
